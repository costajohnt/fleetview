# roost v2 Implementation Plan — zero-config single-server

> **For agentic workers:** Implement task-by-task, fresh subagent per task, review between tasks. Audit-loop convergence at the end.

**Goal:** Kill `roost add`. One detached `opencode serve`; roster auto-populates from `GET /project` — every directory the user has ever run opencode in appears automatically, sessions grouped per project, live status. Sessions opened in plain opencode TUIs show up without any registration.

**Verified live (opencode 1.18.4, this session — do not re-derive):**
- `GET /project` on ANY server → ALL projects globally: `[{id, worktree, vcs, time:{created,updated}, sandboxes}]` (shared opencode.db)
- `?directory=<abs path>` works on `GET /session`, `POST /session`, `PATCH /session/:id`, `DELETE /session/:id` (and header `x-opencode-directory` equivalently). Assume it works on `POST /session/:id/prompt_async` (same routing) — Task 1 tests it against the live server at 127.0.0.1:4801 and STOPS if not (plan invalid).
- `GET /event` is HOME-directory-scoped. `GET /event?directory=X` streams that project's events (`session.created`, `session.updated`, `session.status`, …). One stream per project needed, all to the one server.
- `opencode attach [url] -s <id> --dir <path>` — attach into a session with explicit working dir (CLI docs; e2e-verified in Task 8).

**Architecture (v1 → v2):**
- registry.json (repos, ports, pids) → `~/.config/roost/server.json`: `{host, port, pid}` — ONE record. Port fixed 4900 (avoid v1's 4801 range).
- server-per-repo + port alloc + identity/mismatch subsystem → DELETED. Health = `GET /project` returns 200 JSON array.
- Store/UI keyed by `project.worktree` (abs path, stable, readable) instead of repoId. Group name = basename(worktree).
- Project discovery: `GET /project` at mount + every 30s (new projects appear while roost is open). Projects recency-sorted (`time.updated` desc); sessions within a project recency-sorted, cap 10 visible (unchanged).
- seen.json: same `{key: {updated, hasRun}}` shape, keys now `<worktree>:<sessionId>`. v1 keys become inert orphans — acceptable, file is state not data.
- Launcher: picker lists projects (same filter mechanics, no mismatch filter — subsystem gone). Dispatch = `POST /session?directory=` + `prompt_async?directory=`.
- `roost add` command REMOVED. `roost` with no server → spawns one (detached, cwd = os.homedir()), writes server.json, proceeds.

**What deletes:** registry port allocation + realpath dedupe (file becomes trivial single-record store), mismatch state + UI text, identity compare in server-manager, add-command tests, per-repo spawn loops.
**What survives untouched:** roster/badge/confirm/launcher component mechanics, event-mux reconnect/backoff/decoder, store reducer semantics (waiting/running/done/idle + upsert + seen inference), attach handoff loop, cancelled-flag effect pattern, error→offline guards (offline now per-project: a project whose stream drops shows offline; the single server dying shows ALL offline + roost respawns on next launch).

### Task 1: client.js directory threading (+ live prompt_async probe)
`OpencodeClient` methods gain a `directory` argument appended as `?directory=` query (encodeURIComponent): `listSessions(dir)`, `createSession(title, dir)`, `promptAsync(id, text, dir)`, `renameSession(id, title, dir)`, `deleteSession(id, dir)`. New `listProjects()` → `GET /project` (no directory). Update all client tests (assert URLs incl. encoded query). **Live gate:** against `http://127.0.0.1:4801`, create a session with `directory=/Users/johncosta/dev/roost`, `prompt_async` it with "say ok and stop", poll `GET /session?directory=...` until its `time.updated` bumps, then DELETE it. If prompt_async ignores the directory param (session runs in wrong dir / errors), STOP and report BLOCKED — plan assumption broken. Record the result in the report.

### Task 2: server store + manager simplification
`src/registry.js` → replace contents with single-record store (keep filename registry.js, export `loadServer(file)`, `saveServer(file, {host,port,pid})`, `defaultServerFile()` → `~/.config/roost/server.json`, same ENOENT/corrupt semantics as v1). server-manager: `isServerHealthy` = GET `/project`, ok && Array.isArray(json) → true; anything else false ('mismatch' concept deleted). `spawnServer({host,port}, opts)` cwd = `os.homedir()`, log file fixed `server.log`. killServer/isPidAlive unchanged. Rewrite both test files accordingly (port-alloc, dedupe, mismatch tests deleted).

### Task 3: session-store rekey to worktree
Mechanical rename repoId→projectKey (worktree path) throughout store + tests. `byRepo()` → `byProject()` returning `[{projectKey, sessions}]`. No semantic changes. seen keys become `<worktree>:<id>` automatically via the key function.

### Task 4: event-mux directory scoping
`connectEvents({host, port, directory}, opts)`: URL = `http://host:port/event?directory=<encoded>`; onEvent called with `(directory, event)`. Reconnect/backoff/decoder untouched. Update tests (URL assertions).

### Task 5: app.js — project discovery + rewire
Props become `{server: {host,port}, client, connectEventsImpl, ensureServerImpl, onAction, seen, persistSeen}` (ONE client — no clientFactory map). Mount: `ensureServerImpl(server)` → false = full-screen "server unreachable" message (all-offline state); true → `listProjects()` → for each project: `listSessions(worktree)` seed + scoped event stream. Repoll `listProjects()` every 30s (injectable interval for tests; cancelled-flag pattern); NEW projects get seeded + streamed, vanished ones (rare) left in place until restart. Groups = projects recency-desc, `repoName` = basename(worktree), sessions capped 10 as today. Launcher picker = current projects (name + dim worktree path for disambiguation of same-basename). Dispatch/rename/kill/seen threading: same flows, directory arg. offlineRepos → offlineProjects (per-project stream drops). Mismatch UI text deleted. `onAction enter` payload gains `worktree`. Update all app tests (makeDeps reshaped).

### Task 6: cli.js v2
Drop `add` command entirely (any arg → print usage "roost takes no arguments; it discovers opencode projects automatically"). `main`: loadServer → ensureServer (spawn if dead, poll `/project`) → loop rendering App with server + single OpencodeClient → attach handoff `spawnSync('opencode', ['attach', url, '-s', sessionId, '--dir', worktree], ...)`. seen wiring unchanged (makePersistSeen keyed by projectKey; liveRepoIds → liveProjectKeys). makeEnsureServer: same poll shape minus mismatch branch. Update cli tests; symlink main-guard test survives; add-command tests deleted.

### Task 7: README + smoke v2
README: zero-config story (clone, npm install && npm link, `roost` — that's all; prereqs Node 20+, opencode; sessions from plain opencode TUIs appear automatically; one detached server; server.json/seen.json/log locations; remove-server = kill pid in server.json).
