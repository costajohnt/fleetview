# roost v3 Implementation Plan — Agent View parity: explicit roster, state grouping, peek

> **For agentic workers:** Task-by-task, fresh subagent per task; audit-loop convergence at the end.

**Goal:** Copy Claude Code Agent View's actual model (researched from official docs 2026-07-21): the main list contains ONLY sessions explicitly dispatched from roost or deliberately added ("backgrounded") — not every discovered session. State-first grouping. Peek before attach.

**Agent View facts being copied (from code.claude.com/docs/en/agent-view):**
- "By default the list shows every background session you've started" — membership = dispatched-from-view / explicitly backgrounded; "Interactive sessions you have open in other terminals don't appear until you background them."
- Default grouping by STATE: needs-input top → working → completed bottom (folded); directory grouping is a persisted toggle (Ctrl+S).
- Peek: selecting a row shows the last turn without attaching; Enter attaches fully; detach never stops the session.
- Stop vs delete are distinct; delete removes from the list.

**v3 model on opencode:**
- Membership file `~/.config/roost/roster.json` (ROOST_CONFIG_DIR honored): `{ groupBy: 'state'|'project', sessions: [{worktree, id, addedAt}] }`. Atomic write (pid-tmp+rename) + tolerant load (non-object → default) + corrupt-JSON throw — same policies as seen-store/registry.
- Main view = roster members only. Dispatch via `n` auto-adds. `b` = browse mode: the v2 discovery view (all projects/sessions); `space` toggles roster membership on the selected session; `b`/esc returns to main.
- The v2 "active filter" (`a` toggle, just landed) is REMOVED — membership supersedes it. Browse shows everything unfiltered.
- Main view default grouping: by state — order: waiting ("needs input") → running → error → done → idle. Rows show `badge title · dim basename(worktree)`. `s` toggles to by-project grouping; choice persists in roster.json `groupBy`.
- `x` in main view: Confirm with two accept keys — `y` = remove from roster only (session lives on), `d` = remove AND `DELETE /session/:id?directory=` (hard delete). Browse `x` unchanged (hard delete, existing confirm).
- Peek: `→` on a row opens a pane rendering the selection's last assistant/user turn (client `listMessages(id, dir)` → `GET /session/:id/message?directory=`, take last ~2 messages, render text parts, truncated to viewport); `←`/esc closes back to list. `⏎` still = full attach (opencode owns the terminal; `/exit` returns — unchanged, documented).
- Viewport windowing (landed in the UX round) applies to main, browse, and peek layouts.
- Empty-roster onboarding: "roster empty — n: dispatch a session · b: browse existing sessions".
- seen.json / done-persistence / event streams / server lifecycle: unchanged. Events still stream for ALL discovered projects (browse needs live status too).
