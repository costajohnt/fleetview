# fleetview audit (2026-08-06)

fleetview @ commit `1088e69`, branch `main`, version 0.4.0. 40,407 lines across 153 tracked files. Four parallel review streams (correctness, security, tests, architecture), all CRITICAL/HIGH findings independently re-verified by fresh reviewers. Baseline before audit: `vitest run` → `Test Files  41 passed (41)  Tests  1002 passed | 1 skipped (1003)`; `tsc --noEmit` exit 0.

---

## Critical

None. The seq-watermark protocol, per-worktree seed chain, fold/selection identity handling, PTY teardown, and tail-cursor inode resets were all traced end to end and check out. No injection of untrusted data into shell strings anywhere; `server.json` host pinned to loopback; every disk/wire `JSON.parse` wrapped and shape-checked.

## High

### H1. 2,075-line file / ~1,890-line god component owns everything
`src/app.ts:176-2063` (verified: `App` closes at 2063; three `useInput` handlers inside at 1704/1916/1930). Dispatch (two paths at 1295/1337), selection resolution, fold logic, PR polling (inside the discovery effect at :626), backend registry (227-230), external-roster sync, ghost synthesis, notification, and mouse mapping all live in one closure. Root cause: `rosterRef` (:350), `store` (:222), and `flash` are closure-captured, so any feature needing them must live inside the component — features accrete instead of moduleizing. `usePeek` (used at 1248, taking `reconcileRef` at 1263) proves extraction works but was done once. Fix: repeat the `usePeek` pattern for the discovery/streaming effect (exactly 399-765) and the dispatch pair (1290-1440); the existing refs (`reconcileRef`, `streamProjectRef`, `activateBackendRef` at 342-349) are already the hook boundary.

### H2. Default backend bypasses its own adapter; roster verbs have two code paths
`src/app.ts:251-263, 1290-1343` — `backendFor` returns null for opencode (`:253`) and callers fall through to raw `client.*` (262-263; rename goes raw at 1971 with no adapter lookup at all); dispatch forks at 1343. Verification refined the claim: the no-isolation/no-shell differences are *documented capability absences* (comments at 1298-1300, 1327-1329), not accidental drift — but the shared parts of the fork have genuinely diverged: `dispatchOnBackend` lacks the post-dispatch `listSessions` relist and offline-project bookkeeping the opencode path has (1408-1414). Fix (verified zero-behavior-change): migrate the 1:1 verbs first — `abort`/`delete`/`prompt`/`rename` on the opencode adapter (`src/backends/opencode/index.ts:44-60`) are byte-for-byte the same client calls the null-fallbacks make, so `backendFor` can stop returning null. The dispatch fork stays until the isolation/shell/relist machinery moves out of app.ts.

### H3. "Adding a fourth CLI is a line here plus its own folder" is false
`src/backends/index.ts:2-3` promises it verbatim; `src/backend-normalise.ts:28-52,176-180` contradicts it — `normaliseSessions` and `createNormaliser` are string-keyed if-chains (`if (backend === 'claude')` …), and a fourth backend whose wire format isn't opencode vocabulary silently passes through unnormalised (identity fall-through at :52/:179). Verification refuted half the original claim: the cli.ts policy branches (`:937` env selection, `:940` busyDetachGuard) are binary opencode-vs-everything-else splits, so a fourth *process-backed* CLI gets scrubbed env and the detach guard automatically — no edit needed there. Fix (the load-bearing part only): move `normaliseSessions`/`createNormaliser` onto the Backend contract (opencode's are identity); skip the speculative capability flags.

## Medium

- **M1.** `src/preflight.ts:25-35` — bin entry guard's refusal path never executes in any test. Only the pure `nodeVersionError` is covered; the realpath argv guard, `exit(1)` path, and the dynamic `import('./cli.ts')` catch run nowhere, and CI's pack-and-install smoke only exercises the happy path. Given the 0.2.0 shipped-broken history, the untested half is the install-critical half. Fix: extract the guard body into an exported `run(versions, importImpl, exitImpl)` and test both branches, or spawn `dist/preflight.js` under a faked low version. (unverified)
- **M2.** `test/gated-stdout.test.ts:38,110-118` — fixed 60ms real-timer `tick()` then asserting Ink painted a frame (`widest() > 60`); on a loaded CI runner the frame may not flush in 60ms → flaky failure. Root cause: file predates the `waitFor` polling helper `app.test.ts` uses. Fix: poll `widest()` in a bounded `waitFor` loop. (unverified)
- **M3.** `test/app-notify.test.ts:84-86,116-118` — "does not re-fire agent_needs_input" negative assertions close their observation window after a single 20ms tick; a spurious re-fire on the next (longer) poll cycle would pass, so the regression these tests exist for can return undetected. Fix: wait for one additional `listPermissions` poll (assert call count incremented) before asserting the event count froze. (unverified)
- **M4.** `src/backends/claude/projects.ts:192` → `src/backends/claude/index.ts:333,205` (also `src/backends/opencode/index.ts:47-56`; spawn sites `src/cli.ts:585,920,926`) — disk/server-derived session ids reach child-process argv with no shape validation. Copilot's `parseWorkspace` rejects `/`, `\`, `..` (`src/backends/copilot/sessions.ts:41`) but the claude discovery path has none: a dispatched session can drop `~/.claude/projects/<cwd>/--someflag.jsonl` and attach spawns `claude --resume --someflag` (argument injection surface; actual impact depends on claude's flag arity). Root cause: validation written at the one foreseen path-traversal site, not at the trust boundary where ids enter. Fix: reject ids not matching `/^[A-Za-z0-9_-]+$/` in `listTranscripts` and assert same in each backend's `attach()`. (unverified)
- **M5.** `src/pull-requests.ts:140` + `src/git-safe.ts:20-27,38-46` — `gh` runs in an attacker-named cwd under a git-config denylist whose safety argument was verified only for fleetview's own git commands (`status`/`rev-parse`/`rev-list`); `gh`'s internal git subprocess set is unenumerable, so the denylist is an assurance gap (no demonstrated exec). Fix: add `credential.helper=` and `core.sshCommand=` to `GIT_CONFIG_PARAMETERS` on the gh path — gh authenticates with its own token, so clearing them costs nothing. (unverified)

- **M6.** Tail-a-growing-file machinery triplicated: `src/backends/claude/index.ts:228-279`, `src/backends/copilot/index.ts:395-425` (+ tick state), `src/backends/claude/projects.ts:128-150` — same offset/inode-reset/partial-line/per-file-TextDecoder dance, with comments citing each other ("Same reset, same reasons, as the copilot backend's readFrom"). Fix: one shared `tailFile(cursor, file)` helper so the ino-0-Windows and mid-character-decode fixes land once. (unverified)
- **M7.** `reap()` + `KEEP_RUNS_MS` duplicated verbatim between `src/backends/claude/index.ts:37,92-113` and `src/backends/copilot/index.ts:39,91-111`. Fix: shared `reapRunLogs(dir, now)` next to `ps.ts`. (unverified)
- **M8.** NDJSON chunk parser duplicated: `src/backends/claude/stream.ts:51-66` (`parseStreamChunk`) ≡ `src/backends/copilot/events.ts:21-37` (`parseJsonlChunk`), identical split/pop-rest/try-parse loop. Fix: one shared `parseNdjsonChunk`. (unverified)
- **M9.** Abort pid-recycling guard duplicated: `src/backends/claude/index.ts:344-361` vs `src/backends/copilot/index.ts:349-358`; `PID_MATCH_SLACK_MS` lives in shared `ps.ts` but the logic using it doesn't. Fix: `sameRun(info, id, recordedAtMs, names)` in `ps.ts`. (Same code the security review flagged as the recycled-pid kill window — fix both together.) (unverified)
- **M10.** Backend identity stored in two places needing manual sync: `src/app.ts:235-247` (`sessionBackends` ref map) + `src/session-store.ts:715-718` (`origin` on the record); the app.ts:562-566 comment documents a desync bug that already happened once. Fix: make `backendNameOf` read `store.get(...).origin`, delete the ref map. (unverified)
- **M11.** Config-dir/legacy-fallback + atomic-save pattern triplicated across `src/registry.ts:8-17,113-129`, `src/roster-store.ts:7-14,49-60`, `src/seen-store.ts:6-13,68-78`. Fix: one `paths.ts` + `atomicWrite(file, data)`. (unverified)
- **M12.** Cross-backend inconsistency: tool-denied claude run renders "needs input" (`stream.ts:108`), tool-denied copilot run renders green — `events.ts:70` marks it `completed` and `deniedTools` (emitted at `copilot/index.ts:297`) is dropped by `copilotNormaliser` (`backend-normalise.ts:151-171`). Fix: map `deniedTools > 0` at run end to the same synthetic `needs-input`, or stop emitting the field. (unverified)
- **M13.** Peek "unsupported" for process backends is a null-check, not a capability: `src/use-peek.ts:74-81` switches on `backendFor(target) !== null` while `BackendCapabilities` (`types.ts:147-152`) exists precisely to avoid identity-testing adapters. Fix: add `capabilities.messages` (or `listMessages?`) — blocks feature F2 below. (unverified)
- **M14.** `src/app.ts:499-539` — `seedAndStream` has no re-entry guard; a concurrent double-call (dispatch path at app.ts:1381 vs a poll tick discovering the same worktree — the poll awaits up to 15s of `gh` calls before computing `newOnes`, widening the race) starts two `connectEvents` loops, and `conns.current.set` overwrites one handle so its `stop()` is unreachable: it reconnects every backoff interval and double-delivers events until process exit. Root cause: idempotency enforced only at callers, not in the function. Fix: first line: `if (conns.current.has(worktree) || knownWorktrees.current.has(worktree)) return` (keep delete-on-failure so retries work). (unverified)
- **M15.** `src/use-peek.ts:157` — `flushSavedReplies` can resurrect and deliver a reply the user already superseded: `sendReply`'s success path deletes the key, so "user sent a newer reply directly" is indistinguishable from "nothing happened"; a failed flush's catch then re-queues the stale reply, which a later poll delivers after the newer one — the exact "late reply is a different instruction" failure the module's own comments warn about. Fix: per-key epoch that `sendReply` bumps on success; flush's catch re-queues only if its captured epoch is still current. (unverified)

## Security summary

No critical or high security findings. The hardening that exists is real and deliberate: the only two `sh -c` uses carry untrusted values in env, not the command string; `server.json` host is pinned to loopback (closing the bind-to-LAN/SSRF path); the health probe is deliberately unauthenticated-first; `worktreeName` sanitises to `[a-z0-9-]`; `psInfo` is a genuine chokepoint against `kill(0)`/`kill(-1)` wildcards; packaging is sound (`files` complete, `rewriteRelativeImportExtensions` set, postinstall verified against the real node-pty tree). The residual exposure is two MEDs: session ids entering child argv unvalidated (M4 — the one place a dispatched session could influence a later spawn's flags) and `gh` running in attacker-named cwds under a denylist proven only for fleetview's own git commands (M5). Both fixes are small and additive. The LOWs (password non-burn on `server status`, postinstall TOCTOU, log-file perms, unstripped ids in `ls`, the 60s pid-match window) are defense-in-depth, not exploits.

## Test quality

Unusually strong suite: 41 files, 1003 tests, fixture-driven reducers, injected clocks in pty-host, live armed-hostile-repo security tests in worktree.test.ts, atomic-write checks. Every `src/` file has direct or indirect coverage; the 1 skipped test (`test/pty-real.test.ts:16`) is a deliberate CI-only native-binding check, not a defect. Gaps, in priority order:

1. The bin entry guard's refusal path never executes anywhere (M1) — install-critical given the 0.2.0 history.
2. Two timing-shaped soft spots: a fixed 60ms sleep asserting an Ink frame painted (M2) and negative assertions whose observation window is shorter than the mechanism they guard (M3).
3. `src/git-safe.ts` has no direct test of its `GIT_CONFIG_PARAMETERS` encoding contract; `src/use-peek.ts` (321 lines) is covered only through full-App renders.
4. One test title claims more than its body asserts (`server-manager.test.ts:223-231`); one cleanup deletes env vars instead of restoring them.

## Refactoring map

Sequenced smallest/highest-payoff first; each step is independently shippable.

1. **Delete + docfix batch** (trivial): dead exports `StoreSessionRow`/`TextPart`; stale `types.ts:180-182` contract comment; raw NUL bytes in `copilot/index.ts:284` → `\u0000` escapes; dedupe the opencode capability-flag triplicate.
2. **Shared-mechanics extraction** (S, mechanical): `atomicWrite` + `paths.ts` (M11), `reapRunLogs` (M7), `parseNdjsonChunk` (M8), `sameRun` pid guard in `ps.ts` (M9 — fixes the security 60s-window LOW in one place).
3. **`tailFile(cursor, file)`** (M, the highest-payoff dedupe): collapses the triplicated tail machinery (M6) so inode-reset/partial-decode fixes land once.
4. **Kill the `sessionBackends` ref map** (S): store `origin` is the durable copy (M10).
5. **Adapter honesty** (M): migrate opencode's 1:1 verbs onto its adapter (H2), then move normalisers onto the Backend contract (H3).
6. **App decomposition** (L): extract the discovery/streaming effect and the dispatch pair as hooks along the existing ref boundaries (H1). Do this after 4-5 so the extracted hooks close over one backend-identity source and an honest adapter.

## Feature opportunities (ranked)

1. **F1 (M) — `fork()` on the Backend contract + claude fork support.** `claude/index.ts:21-22` states it outright ("`--fork-session` exists; the contract has no fork() yet"); `/fork` in app.ts calls `client.forkSession` directly. Contract work, not research.
2. **F2 (M) — peek transcripts for process backends.** `use-peek.ts:79` renders "unsupported", yet both transcript parsers already exist (`projects.ts` for claude, `events.ts` for copilot). A `Backend.listMessages(ref)` returning the `{info, parts}` envelope lights up peek for all three backends. Unblocks after M13.
3. **F3 (S) — per-row run cost/duration for claude sessions.** `costUsd`/`durationMs` are already parsed and folded (currently dead — see Low); one normaliser emission plus a peek line turns dead fields into the only cost telemetry any backend offers.
4. **F4 (S) — surface opencode's `retry` payload.** `types.ts:42` types the full retry action but fleetview reads only `.type`; a rate-limited session shows a plain spinner while the server says exactly why and until when.
5. **F5 (M) — multi-backend `fleetview bg`/`ls`.** `runBg` is hard-wired to the opencode client though `createBackends` exists in the same file and the roster-membership shape already carries `backend`. Mostly plumbing `backend.dispatch` into runBg.
6. **F6 (S) — backend preflight/health.** `streamBackend`'s catch deliberately conflates "CLI not installed" with "no sessions"; the `--version` probe cli.ts already runs for opencode, applied at `activateBackend` time, lets the roster say "claude not installed" at dispatch.
7. **F7 (L) — fleetview-owned worktree isolation for process backends.** `dispatchOnBackend` ships unisolated with an apology notice, but `worktree.ts` + `git-safe.ts` + `removeWorktreeFor` already contain the machinery; `git worktree add` run by fleetview gives claude/copilot dispatches the same safety story.
